# Pruebas

**Criterio:** cada prueba fija un comportamiento que un evaluador podría verificar a mano, o una propiedad que un error real rompería. Nada se escribe para subir cobertura.

```bash
pnpm test           # todo; necesita un Postgres (TEST_PG_URL)
pnpm test:unit      # solo las unitarias, sin base
```

El CI (`.github/workflows/ci.yml`) corre `typecheck`, `test:unit` y `test:db` en cada PR contra un Postgres 18 de servicio, después la compatibilidad con el release anterior (`scripts/previous-release.sh`, abajo), `docker build` desde el checkout limpio y el smoke funcional contra esa imagen (`deploy/lightsail/smoke-docker.sh`, abajo).

Las pruebas con base crean su propia base de datos `cocos_test` desde cero, con **el mismo bootstrap que producción** (seed del challenge, migraciones, funciones). Cada prueba usa usuarios nuevos: las órdenes no se pueden borrar, así que nadie hereda estado de otra prueba. Por defecto `TEST_PG_URL=postgresql://postgres:postgres@localhost:5432/postgres`, que es el Postgres de `docker compose up`.

## Lo que no está cubierto

- Parte del deploy contra el servidor real. `test/unit/deploy-workflow` ejecuta los jobs contra un servidor simulado; `deploy/lightsail/drill-docker.sh` corre `remote.sh` a mano con Docker real (un bootstrap roto y una API sin salud rechazados, y la vuelta atrás; los secretos de archivo con los permisos de `setup.sh`, y que `docker inspect` de `db`, `migrate` y `api` no muestra ninguno), y con Caddy delante ninguna request falló durante un cambio. El primer release, v0.1.0 (30-10-2026), ejercitó el workflow con los secretos de verdad, los certificados de Caddy y el volumen de Postgres: gate, imagen, staging y producción en verde (el primer deploy de cada entorno), `/health` de los dos entornos atendiendo `159b0f0` por HTTPS con certificados de Let's Encrypt, y `deploy/drills.sh release v0.1.0` OK. Contra el servidor real sigue sin ejercitarse la vuelta atrás, el gate de ancestría (`deploy/drills.sh rerun`, a mano) ni un segundo deploy sobre uno existente ([D-29](decisiones.md#d-29)). El smoke funcional ([#51](https://github.com/dante0x95/cocos-challenge-a/issues/51)) corre en el CI contra la imagen con Docker real, pero contra staging y producción (Caddy, HTTPS, la base de staging con su historia) recién con v0.2.0.
- `docker compose up` de punta a punta: el CI construye la imagen y el bootstrap (`test/bootstrap`) cubre lo que corre el contenedor `migrate`, pero nadie levanta los contenedores.
- Rendimiento: se midió aparte, con el benchmark descripto en [`decision-snapshot.md`](decision-snapshot.md). No es parte de la suite.
